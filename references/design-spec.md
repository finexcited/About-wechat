# 设计与长图处理规范（考公类公众号）

## 一、封面图规范

**主方案（v3 AI 混合模式）**：ImageGen 生成无文字创意背景（`scripts/compose_cover.py` 合成）——AI 提供设计感和新颖构图，程序保证中文标题零错字、LOGO 精确、900×383 合规。

**备用方案（v2 程序版）**：`scripts/make_cover.py`——零积分消耗、风格统一，积分不足或用户要求快速出图时用。

### v3 工作流（每天 N 张，N = 每日篇数）
1. **按标题内容为每篇设计 AI 背景提示词**，要求：
   - 固定元素：米白底 `#F8F5F0`、主色橙 `#EE7800` / 绿 `#007E5C`、右侧放视觉主体、左侧留大面积空白给文字
   - 风格轮换保证新颖：扁平插画 / 等距 3D / 剪纸风 / 渐变几何 / 手绘线稿 / 低多边形 / 柔和水彩 / 像素风等
   - 视觉主体与标题语义匹配（岔路口=选择、大楼=职能、日历=时间线、放大镜=信息差、学士帽=应届生）
   - **结尾必须加：绝对不要出现任何文字、字母、数字、二维码、水印**（AI 文字不可靠）
   - 尺寸 `1536x1024`，quality high
2. **合成**：
   ```bash
   python3 \
     "$SKILL_DIR"/scripts/compose_cover.py \
     --bg AI背景.png --title "考公还是就业\n大四怎么选" \
     --subtitle "两条路的时间线都帮你算好了" \
     --keywords "国考|省考|秋招|时间线" \
     --panel left --focus_x 0.6 \
     --out $WX_DAILY_OUT/标题_YYYY-MM-DD_封面.png
   ```
3. **检查背景质量**：若 AI 背景左侧不干净（元素侵入文字区），换 `--panel center` 或重新生成；`--focus_x 0.5-1.0` 控制裁切重心保住右侧主体
4. **衬板模式**：left（默认，左侧半透明米白卡）/ center（居中卡）/ bottom（下半通栏）；背景本身留白干净时可 `--no_panel`（自动加暗部渐变）

### 成本提示（必须告知用户）
- ImageGen 每张约 5—10 积分，每天 N 张封面 ≈ N×5 到 N×10 积分（准确数跑 `cost_estimate.py`）
- 用户未明确接受积分消耗时，用 v2 程序版（零积分）或先询问

### 通用规范（两个方案共用）
- **色系不是固定的**：主色 `WX_ACCENT`、辅色 `WX_ACCENT_ALT`（任意 `#RRGGBB`），多篇交替使用；下文出现的橙/绿只是示例预设取值
- 尺寸 900 × 383 PX，PNG；保存 `$WX_DAILY_OUT/标题_YYYY-MM-DD_封面.png`
- **文字零特效（用户明确要求）**：标题/副标题/关键词条一律单层实色渲染，禁止阴影、描边、发光、渐变、重复绘制——避免重影
- **中文一律由程序绘制（不靠 AI 生成），杜绝错字**
- **字体只有一个，没有回退**：PNG 侧只用 `assets/fonts/NotoSansSC-VF.ttf` 绘制，字符不在该字体里就画成 `.notdef`（带叉的方框）。实测 `✅ 🔥 📌 👉 🎯` 全是同一个叉框，藏文 `བ`、梵文 `क`、扩展汉字 `𠮷` 也一样；而 `⚠ → ※ ① ▪ ◆ ● ★ ☆ ✓` 有字形、正常显示。三个出图脚本（`make_long_image.py` / `make_cover.py` / `compose_cover.py`）默认剥离渲染不出的字符并打 WARN（`--keep-emoji` 保留），HTML 版不受影响——所以正文该不该写 emoji，见 `content-guidelines.md` 的「表情符号（三选一）」（Q35）。
- LOGO 角标：`assets/logo.png`（自有品牌版，仓库内为占位图），右上角，24PX 安全边距，白色衬底，不修改/换色/变形
- **不体现 LOGO 时（`WX_LOGO=none`）**：右上角留空，脚本整块跳过——**不会**改印一行品牌名。排版不用改，但要知道两个副作用：① 右侧顶部只剩副标题一根，视觉重心更偏左，这是素封面该有的样子；② 少了一个色块，封面整体更「干净」也更「平」——如果觉得太空，把重点句卡片或关键词条做厚一点比硬加图形稳妥
  - **尺寸预算**：角标高度固定 56PX（`compose_cover.py`）/ 64PX（`make_cover.py`），宽度由宽高比推出，但**限定在画布宽的 28%（252PX）以内，下限 40PX**。越界时脚本压到边界并打 WARN，不会硬拉出画面。
  - **源图规格**：透明底 PNG、高度 ≥128PX（两倍余量）、宽高比 1:1—6:1（420×140 ≈ 3:1 最贴现有版式）。低于 128PX 会被拉糊，超宽会被压成一条横线，超窄会压成一条竖线——三种都不报错，靠 `bootstrap.py --report` 与出片核验（Q34）拦。

- 禁止出现：公众号名称文字、二维码、未授权图片/肖像/商标
- 字体：Noto Sans SC（OFL 免费商用，assets/fonts/）
- 底部关键词条：底色＝辅色、字色＝白（`--bar` / `--bar_ink`），从文章小标题提炼 3—4 个，`|` 分隔 + 主色圆点
- **底色/字色/条底色一起改时（Q20 选 2）必须过对比度**：`pick_palette.py --check <底> <字>`。≥4.5:1 通过；3.0—4.5 仅够封面标题这种大字号；<3.0 脚本 `exit=4` 拒绝，别硬渲。条底色偏浅（明度高）时把 `--bar_ink` 换成深色，否则白字糊在浅底上

### 文案长度上限（超了会被右侧裁切，脚本会提示但不阻断）

封面是 900×383 的固定画布，文字不换行就必然溢出。实测可用宽度与建议字数：

| 位置 | 可用宽度 | 实测上限 | 超限表现 |
|---|---|---|---|
| v2 版式1 标题行 | 470px（74pt/900，超了自动缩字号） | **≤ 6 字/行**（保住 74pt） | 不裁切，掉字号 |
| v2 版式1 副标题 | 272px（**实际固定 34px**） | ≤ 8 字 | 右侧被裁 |
| v2 版式2/3/4 副标题 | 814px（26pt/400） | ≤ 31 字 | 右侧被裁 |
| v3 left 衬板 标题行 | 约 418px | ≤ 15 字/行 | 压到衬板外 |
| v3 left 衬板 副标题 | 约 392px（26pt） | ≤ 14 字 | 压到衬板外 |
| v3 center 标题行 | 约 592px | ≤ 22 字/行 | 超出居中区 |
| v3 bottom 标题行 | 约 840px | ≤ 32 字/行 | 贴边 |

> **这张表是「手写参考值」，脚本每次会按真实字宽重算一遍**，`warn_text_fit()` 的算法是 `建议 = 可用宽度 ÷ 实际单字宽`，所以它说的数比表里准——**冲突时信 WARN**。

### 两条容易看错的真实行为（2026-11-04 实测）

**① 版式1 标题行：上限 6 字，但超了不会裁切，会掉字号。**
`warn_text_fit` 用的是**固定 74px** 量宽度，所以 7 字（518px > 470px）一定 WARN；而实际渲染走 `draw_mixed_title → fit_lines`，按 `while size >= 34: size -= 4` 自动缩字号，7 字缩到 66px（462px）就放得下了。
→ 所以 WARN 里的「可能被裁切」在标题行上是**保守误报**：不会裁，但 74px 的大字号会掉到 66/62/58……**字号层级变了，视觉冲击就没了**。6 字是「保住 74px」的物理上限，不是抄来的数字。
（本表原来写「≤8 字/行」，实测 8 字 592px、9 字 666px，怎么算都超——是错的，已订正。）

**② 版式1 副标题：上限就是 8 字，9 字真的会裁。**
副标题走 `fit_lines(…, base_size=32)`，但那个函数的循环下限是 `while size >= 34`——**32 < 34，一次都不循环，直接落到兜底 `load_font(34)`**。也就是说副标题实际恒定渲染在 **34px**，不是文档写的 32px。
→ 8 字 = 272px 正好等于可用宽度（压线通过）；9 字 = 306px 超 34px，**真裁**。想让副标题小一点也不行，字号是被 `>= 34` 这个硬下限锁死的（改代码才能动）。
（这条同时解释了为什么 WARN 里的建议值恰好是 8：`272 ÷ 34 = 8`。）

**写法建议**：标题用 `\n` 主动分行，每行控制在 **≤6 字**（对比式尤其），副标题只写一句、**≤8 字**、别堆定语。脚本超宽时的提示长这样：
`WARN: 版式1 副标题「…」宽 306px 超出可用 272px，可能被裁切；建议 ≤8 字（或换行）` —— 看到就改，不要忽略。

## 二、v2 程序版封面（make_cover.py，备用）

4 套版式：1 对比式（绿橙混排+图标卡片）/ 2 大字焦点式（字符水印）/ 3 标签卡片式 / 4 深绿问答式。按标题类型选择：对比类→1、疑问/数字类→2 或 4、身份/窗口类→3。

```bash
python3 \
  scripts/make_cover.py \
  --title "选调生\n普通公务员" --vs "vs" --subtitle "大学生该冲哪一个？" \
  --icons "check,doc" --icon_labels "普通选调,国考" \
  --keywords "门槛|考试|发展|适合人群" --variant 1 --out 封面.png
```

图标库：doc（材料）/ check（条件）/ cal（时间）/ search（信息差）/ cap（毕业）/ flag（目标）。

## 二、长图规范（两条路线）

### 路线 A：模板替换（Q18 选 `1` 时用，scripts/long_image.py）

- 模板目录：`$WX_DAILY_OUT/模板/长图模板.png`（固定目录方案，用户按需手动替换新模板）
- 输出：宽 1000PX，高度按模板等比，PNG
- 保存：`$WX_DAILY_OUT/标题_YYYY-MM-DD_长图.png`
- **铁律：只改文字，不动图形。** 不修改、不删除、不更换图形格式、图标、色块、边框、背景、Logo、二维码、装饰元素

### 路线 B：自创版式（Q18 选 `2` 时用，scripts/make_long_image.py v3 图文并茂版）

```bash
python3 \
  scripts/make_long_image.py --md 标题_YYYY-MM-DD.md --accent orange \
  --art 头部插画.png --insert 图1.png,图2.png --out 标题_YYYY-MM-DD_长图.png
```

- 宽 1000PX，高度按内容自动计算（典型 4500—5500PX），PNG
- 直接从文章 Markdown 排版：`#` 大标题 / `##` 小标题 / 段落 / `**加粗**` / 整段 `**加粗**` = 重点句卡片 / `>` 来源备注
- 字号分级：大标题 54（900）/ 小标题 36（800，绿色）/ 重点卡片 31（700）/ 正文 29 / 备注 22（灰色）
- 行距 1.7，段间距 26，页边距 72

**v3 图片内容（图文并茂，用户要求增强）**：
- `--art` 头部横幅插画：通栏圆角卡（1000 内宽 × 320PX，cover 裁切），置于标题区下方，是长图的第一视觉焦点
- `--insert` 中段插图卡：可传多张（建议每篇 2 张），自动均匀插入各章节之间（圆角卡 + 细边框 + 上下 36PX 留白，最大高 440PX）
- 插画用 ImageGen 生成（每张约 5—10 积分）：提示词按文章具体内容设计场景（如"翻岗位表→放大镜查表格卡""时间线→日历墙""选岗决策→对比卡片"），固定米白底 + 橙绿主色 + 结尾禁文字
- 积分成本：每篇长图 3 张插画 ≈ 15—30 积分，篇数 × 15—30 即每天的上限区间；用户未接受时降级为纯程序版（v2 设计元素仍保留）

**v2 设计元素（保留）**：章节序号徽章（橙绿交替）、小标题主题线性图标、小标题点线、重点句卡片、头部双色带、装饰圆点、标题双色下划线、底部备注区。

文字零特效：单层实色渲染；中文程序绘制，无错字风险。

### 路线 C：HTML 格式版（公众号排版样式，scripts/make_article_html.py）

用户在第四步格式询问中选"HTML 格式版"或"两个版本都需要"时走此路线。

```bash
python3 \
  scripts/make_article_html.py --md 标题_YYYY-MM-DD.md --accent orange \
  --art 横幅插画.png --insert 图1.png,图2.png --out 标题_YYYY-MM-DD_推文.html
```

- **定位**：适合直接发布到公众号的排版样式，目标提升阅读完成率与收藏率；读者为在校/即将毕业/刚毕业大学生
- **配色**：橙 `#EE7800` / 绿 `#007E5C` / 米白底 `#F8F5F0` 为主，辅色克制（灰系），简洁高级
- **版式要素**：
  * 头部双色带 + 大标题 + 双色下划线（与 PNG 长图品牌一致）
  * **导读摘要框**：文章开头段落放入米白圆角卡 + 橙色"导读"标签，3 秒让读者判断值不值得读
  * 序号徽章小标题 + 主题线性图标 + 点线分隔区
  * **重点句高亮**：Markdown 行内 `**加粗**` → 荧光橙底加粗
  * **金句卡片**：整段 `**加粗**` → 米白重点框 + 主题色左条
  * **结尾引导关注块**："写在最后"区，引导收藏、转发、关注你的公众号
  * 信息来源备注（虚线分隔，灰色小字）
- **插图**：根据小标题/重点句用 ImageGen 创作场景插画（可与 PNG 版共用同一组）；横幅置顶 + 中段插图均匀分布；正文宽度 677PX 自适应，避免全文字
- **输出**：自包含 HTML（图片 base64 内嵌，单文件可转发），保存 `$WX_DAILY_OUT/`
- 文字纯 CSS 实色渲染（无阴影无重影）；中文程序渲染，无错字风险

### 路线 A 工作流程
1. 用视觉能力读取模板图，识别各文字模块（标题/小标题/正文）的位置、字号、颜色、对齐方式
2. 按模板坐标系（模板会先等比缩放到宽 1000PX，坐标基于缩放后的图）编写 layout.json
3. 每个文字块：擦除原文字（脚本自动用周边背景色填充）→ 绘制新文字（自动换行、行距 1.5—1.8、字号自动收缩防溢出）
4. 正文内容多、模板模块不够时：用 `copy_rect` 复制模板中已有的正文模块到空白位置（保持同样图形样式），再填入文字
5. 多余文字占位：`text` 置空即仅擦除不填字，图形不变

### layout.json 示例
```json
[
  {"rect": [50, 40, 900, 80], "text": "大四才开始考公，晚吗", "font_size": 44, "weight": 900, "color": "#231815", "align": "center"},
  {"rect": [80, 160, 840, 300], "text": "正文第一段……", "font_size": 30, "weight": 400, "color": "#231815", "line_spacing": 1.6},
  {"rect": [80, 500, 840, 300], "copy_rect": [80, 160, 840, 300], "text": "复制模块后的正文……"}
]
```

### 技术优先级
1. 模板为 PSD / Figma / HTML / 分层文件 → 提示用户导出为 PNG 后再处理（当前脚本只支持图片模板）
2. 模板为不可编辑图片 → 本脚本方案（区域擦除 + 原风格重绘）
3. 擦除文字会破坏图形（文字与图形交织、背景复杂纹理）→ **停止处理，输出异常说明，不破坏原图**

### 字体匹配
- 模板原字体未知时，优先用 Noto Sans SC 匹配黑体系模板风格；宋体/楷体风格可用霞鹜文楷（需另行下载）
- 禁止使用未授权商用字体

## 三、文件命名

- Markdown：`标题_YYYY-MM-DD.md`（标题含 `/ \ : * ? " < > |` 时替换为空格）
- 长图：`标题_YYYY-MM-DD_长图.png`
- 封面：`标题_YYYY-MM-DD_封面.png`
- 总清单：`00_当日总清单_YYYY-MM-DD.md`
- 执行日志：`00_执行日志_YYYY-MM-DD.md`
- 当日所有文件均在 `$WX_DAILY_OUT/` 下（模板在 `模板/` 子目录）
