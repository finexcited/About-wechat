# 首周反馈环（跑满 7 天再调参）

配好就跑、跑完不管，是这套技能最常见的浪费。**篇数、选题、封面方案这三件事，只能靠数据定，不能靠感觉定。**

本文档给一张记录表和一套判定规则。7 天后照表调参——但**改哪里**比改多少更容易出错，所以第三节单独讲。

---

## 零、这份记录放哪、叫什么

- 位置：`$WX_DAILY_OUT/00_首周记录.md`
- **文件名必须 `00_` 开头**。`check_content.py` 靠这个前缀把非稿件文件排除在质检之外，写成 `首周记录.md` 会被当成一篇稿子：

  ```
  [FAIL] 首周记录.md  「首周记录」 24字
          ✗ 正文 24 字，不足 800 字下限
          ✗ 缺少互动问题（正文/结尾应有提问）
          ✗ 缺少收藏/转发引导
  结论：3 项必改
  ```

  一张记录表被报三条跟它毫无关系的错。改名加 `00_` 立刻消失。
- Q43 选 `2`（我自己记）或 `3`（不复盘）时**不建这个文件**——建了不填，等于给自己留一个假的完成标记。

## 一、每天记 3 个数（2 分钟）

打开公众号后台「内容分析 → 单篇数据」，抄进下表。

| 日期 | 篇数 | 平均阅读完成率 | 平均收藏率 | 涨粉 | 备注（哪篇明显好/差） |
|---|---|---|---|---|---|
| D1 | | | | | |
| D2 | | | | | |
| D3 | | | | | |
| D4 | | | | | |
| D5 | | | | | |
| D6 | | | | | |
| D7 | | | | | |

**为什么只看这三个**：阅读量受粉丝基数影响，新号没有可比性；完成率反映内容质量，收藏率反映"有用程度"（最该追的指标），涨粉反映拉新。三者都不需要等一周才波动。

> 后台字段名各版本不同（「阅读完成率」也可能叫「读完率」，「涨粉」在「用户分析 → 新增关注」）。**按含义找，别按名字找**；找不到就记你能拿到的三个最接近的。

## 二、第 7 天做 4 个判定

下面的阈值（30% / 45% / 3% / 40 分钟）是**经验起点，不是行业标准**。跑满一周后按你自己的基线重定一次——新号和老号、考公号和母婴号，基线都不一样。

### 判定 1：篇数够不够

| 观察 | 结论 | 怎么改 |
|---|---|---|
| 完成率 < 30%，且自己审稿时间超过 40 分钟/天 | **过量**，内容注水 | 篇数下调一档（如 5→3）。改的是 `WX_ARTICLES` 环境变量，**不是 `00_配置.md`**——见第三节 |
| 完成率 > 45%，收藏率 > 3% | 供给不足或读者粘性好 | 保持篇数；有余力给专栏加 1 篇（`WX_SERIES` +1） |
| 完成率 30—45% | 正常区间 | 不动 |

### 判定 2：哪类选题该加密

把 7 天里收藏率最高的几篇拉出来（不足 3 篇就全取），看它们落在哪个主题上。主题来自你自己的 `00_主题词表.json`，用 `python3 scripts/topic_registry.py stats --days 7` 看分布最快。

- **收藏率前 3 的主题，下周占比提到 50% 以上**
- **连续 7 天收藏率为 0 的主题，从选题池里移除或降权**
- 若 `stats` 输出里「其他」占比 ≥30%，说明词表没覆盖这些选题——先按 Q33 补词表，再谈加密哪一类（否则你是在给一个归类错误的分布做决策）

### 判定 3：封面方案要不要留 AI

| 观察 | 结论 |
|---|---|
| 同一篇换封面后阅读率无明显变化（±5% 内） | AI 背景不值得，改纯程序版，省下全部封面积分 |
| 纯程序版明显偏低（>15% 差距） | 保留 AI 背景，但可只给头条用 |

> 判定 3 需要做一次 A/B：同一篇文章不换内容，只换封面，隔 3 天再发一次（或用两篇同类文对照）。小号做 A/B 会打扰读者、样本也太小——**没条件就按「先纯程序版跑一周」处理**，省下的积分比盲猜更值。

### 判定 4：语气像不像人写的

抽几篇成品（不足 3 篇就全取），遮住署名给自己或同事读，问一句：**"这像不像一个人在说话？"**

- 像 → 不动
- 像报告 / 像 AI → 回 `references/content-guidelines.md` 的「四、去 AI 味清单」，把命中的句式加进「### 禁用句式」（用 `/` 分隔），再跑 `check_content.py --dump-lexicon` 确认生效

## 三、改哪里才会真的生效

这是最容易白改的一节。同一个「篇数」，写在 `00_配置.md` 里不起作用——**脚本只认环境变量**。实测：

```
$ WX_ARTICLES=5 python3 -c "…from brand import article_plan; print(article_plan())"
(5, 2, 3)

# 00_配置.md 里写「每日总篇数：3」，环境仍是 5
md 里写 3、环境是 5 → (5, 2, 3)      ← 篇数没变
```

所以先分清两类字段：

| 类别 | 有哪些 | 真源 | 改法 |
|---|---|---|---|
| **脚本读的** | 类目 / 读者画像 / 主色 / 辅色 / 规范文件 / 输出目录 / 篇数与专栏 / LOGO | 环境变量（`~/.zshenv`）+ 规范文件 | 改环境变量，**再把 md 同步一次**（md 只是镜像，用于人和 AI 阅读） |
| **只有 AI 读的** | 成品形态 / 人工审核 / 节假日策略 / 产物保留 / 配图策略 | `00_配置.md` | 改 md 就够。**没有命令能验证它生效**，只能靠下一次运行时 AI 是否照做 |

四类改动各自怎么验：

```bash
# 1) 改了篇数 / 专栏篇数 → 验三元组 (总篇数, 专栏数, 泛干货数)
python3 -c "import sys;sys.path.insert(0,'scripts');from brand import article_plan;print(article_plan())"

# 2) 改了词库 / 字数区间 / 标题上限 → 这些写在**规范文件**里，脚本实时解析，改文件即生效
python3 "$SKILL_DIR"/scripts/check_content.py --dump-lexicon

# 3) 改了主色 / 辅色 → 出一张封面看，或让脚本判定「是不是彩色」
python3 "$SKILL_DIR"/scripts/check_cover_color.py <封面图> --json

# 4) 改了成本相关的方案（封面/配图）→ 重新估算
python3 "$SKILL_DIR"/scripts/cost_estimate.py --articles 3 --cover prog --illust 0
#    注意：这条的参数得自己带新值，它**不会**去读你的配置
```

> 第 2 类是唯一「改文件就生效」的——规范文件是真源。第 1、3、4 类都靠环境变量，篇数的变化**只看 dump-lexicon 是看不出来的**，必须跑第 1 条。

最后确认一遍四类都是新的（一条命令盖住环境与 md 的一致性）：

```bash
python3 "$SKILL_DIR"/scripts/bootstrap.py --report
# 看「00_配置.md（Q40）」这行：不一致会把「md 写着 X，脚本实际用 Y」逐项列出来
```

## 四、第二周开始只做一件事：守住节奏

首周调完参数后，第二周**不要再调**。日更号的价值在稳定输出，不在每天优化。

需要再调参的触发条件只有三个：

1. 完成率连续 5 天跌破 25%
2. 收藏率连续 7 天为 0
3. 考试/行业公告发布（政策类选题临时加密，见「节假日策略」字段）

除这三种情况，第 8—30 天只记录、不改配置。
