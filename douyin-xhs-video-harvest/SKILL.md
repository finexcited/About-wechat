# 抖音 / 小红书视频采集

## 目标

从抖音或小红书找到并交付 3 条符合用户偏好的视频。每条必须满足：

- 竖版 9:16，比例误差不超过 2%。
- 短边至少 1080 像素。
- 画面中没有明显平台水印。
- 已移除剪映 / CapCut 标识、导出时间、设备标识等容器元数据。
- 清理过程不重新编码，分辨率、时长和视音频流保持原样。

若最终不足 3 条，交付实际合格的视频，并说明数量不足的原因和放宽建议，不要用不合格文件凑数。

只处理用户有权使用的内容。需要发布、商用或二次分发时，提醒用户自行确认素材授权。

## 操作边界

- 使用 `$ego-browser` 操作 ego lite。开始前读取该技能的说明，并遵循其浏览器操作方式。
- 在独立的 ego lite Space 或标签页中检索，不接管或关闭用户正在使用的页面。
- 登录态只通过 ego lite 继承。需要登录时请用户扫码，不索取密码、Cookie、Token 或验证码。
- 参考图片或视频只作为风格锚点，不得把参考媒体本身当成检索结果或交付物。
- 未收敛检索条件前，不进入批量搜索、下载或清理。
- 不凭标题、标签或封面文字臆测视频画面。页面信息不足时标记“不确定”，必要时打开视频查看关键帧。
- 同一视频用平台视频 ID、规范化 URL 或明显的画面指纹去重。
- 优先使用本机 CLI、ego lite 页面能力或本地 MCP 解析无水印直链。不得把用户视频上传给要求上传文件的第三方解析服务。

## 输入与默认值

用户可以提供以下任一组合：

| 输入 | 要求 |
| --- | --- |
| 搜索关键词 | 至少与参考媒体二选一 |
| 参考图片 / 参考视频 | 至少与关键词二选一；可为本地文件或可访问链接 |
| `platform` | `douyin` 或 `xiaohongshu`；未指定时先确认 |
| `output_dir` | 可选 |

若关键词和参考媒体都没有，先请用户提供其中一个，不要自行编造主题开搜。

默认输出目录：

```text
~/Downloads/video-harvest-{platform}-{slug}-{YYYYMMDD}
```

`slug` 取关键词或参考主题的简短英文/拼音描述，并移除文件系统非法字符。

## 阶段 1：前置检查与锚点解析

不向用户提问，先完成以下准备：

1. 确认 ego lite 可操作，并把目标平台打开在独立 Space。
2. 检查平台登录态；未登录时请用户扫码，等待用户明确回复后再继续。
3. 若提供了参考媒体，提取视觉画像：

```text
主体类型、人物性别/年龄感/是否露脸、服装风格、色调、场景、
景别与构图、字幕/贴纸风格、剪辑节奏、推断受众
```

用 `ffprobe` 或参考媒体的播放信息读取分辨率、宽高比和时长。参考媒体的规格只作为排序依据，交付仍须满足 9:16 和短边 1080 的硬门槛。

若只有参考媒体、没有关键词，根据“主体 + 场景 + 风格”生成 1–3 个候选搜索词，先请用户确认，不直接开搜。

## 阶段 2：最小化问询

在提问前读取 [references/condition-pool.md](references/condition-pool.md)，用它把已知信息整理成 `condition_pool`。

### 有参考媒体

参考媒体已经回答了主体、人物与风格，最多问一个必问项：

```text
有没有必须排除的？（可多选，没有就回复“无”）
① 横版/非竖版
② 低于 1080P
③ 带明显水印
④ 广告/带货硬广
⑤ 与参考视频过于雷同（疑似同一条）
⑥ 无
```

若没有关键词，再确认阶段 1 生成的候选搜索词。确认搜索词不额外占问询轮次。

### 只有关键词

第一轮固定问两项，均支持多选：

```text
Q1 你想要的视频，画面主体是哪种？
A. 真人出镜口播/讲解
B. 真人穿搭/展示（可不说话）
C. 剧情/情景演绎
D. 纯产品/画面展示（无真人）
E. 都行

Q2 有没有必须排除的？
① 横版/非竖版
② 低于 1080P
③ 带明显水印
④ 广告/带货硬广
⑤ 无
```

仅当 Q1 为 A/B/C，且用户首条消息没有说明人物性别或风格时，再问：

```text
Q3 出镜人物更偏向？
A. 女性 + 日常/休闲
B. 女性 + 职场/精致
C. 男性 + 日常
D. 男性 + 商务/潮酷
E. 不限
```

Q1 为 D/E 时跳过 Q3。纯关键词路径最多 2 轮、4 个问题；参考媒体路径最多 1 轮、2 个问题。

用户已经说明“形式、性别、风格”中的至少两项，或回复“随便 / 都行 / 你看着办”时，不再追问。复述推导出的 `condition_pool` 并问“这样对吗？要改哪条？”，得到确认后搜索。

## 阶段 3：搜索与筛选

1. 用确认后的关键词搜索。
2. 每批读取前 10 条的标题、博主、封面、时长、关键帧和可见标签。
3. 先按硬条件过滤：用户排除项、9:16、短边 ≥1080、主体类型。
4. 再按参考画像、Q3 人物锚点和软条件排序。软条件只加分，不作为淘汰条件。
5. 合格数达到 3 条立即停止检索。
6. 不足 3 条就读取下一批，累计最多检查 50 条。

用户排除了“与参考视频过于雷同”时，明显同源的视频直接跳过；用户未排除时，可以保留为候选，但必须提示“疑似与参考同源”。

累计 50 条仍不足 3 条时停止，报告：

- 实际合格数量和已检查数量。
- 最严格的过滤维度。
- 可放宽的条件，例如主体形式、相似度或排除项。
- 请求用户决定是否继续。

## 阶段 4：无水印获取与初检

对每条候选记录原始页面 URL、平台视频 ID、博主名和关键画面。

优先从页面或本地工具取得无水印视频直链，下载到临时目录。每下载一个文件，立即运行：

```bash
python3 <skill-dir>/scripts/media_guard.py inspect <file>
```

脚本返回 JSON；只有同时满足以下条件才进入清理：

```text
decode_ok = true
vertical = true
aspect_ok = true
short_side >= 1080
```

如果为横版、短边不足、无法解码或视频损坏，丢弃并回到检索阶段补位。

下载和解析失败必须记录 URL、失败阶段和错误摘要。不要用带明显水印的备用下载冒充合格结果。

## 阶段 4.5：中文语音处理

对每条通过初检的候选检查音轨。以音轨中可辨识的连续中文对白、旁白或口播为准，字幕和标题只用于辅助判断；背景音乐、歌曲中的个别中文词或环境声不算“明显中文语音”。

发现明显中文语音后，必须在最终导出前让用户选择，除非用户在当前任务中已经明确指定：

```text
检测到该视频含明显中文人声，请选择处理方式：
1. 删除中文人声，保留背景音
2. 删除中文人声并合成为指定语言的 AI 配音
3. 两种版本都导出
```

若选择第 2 或第 3 项但没有目标语言，只追问目标语言。多个候选都含中文语音时，可询问是否统一应用同一选择。

执行约束：

- 必须实际分离人声与背景音，不得仅降低原人声音量，也不得把目标语言配音直接叠在原人声上。
- 删除人声时保留 `no_vocals`/伴奏轨；合成配音时使用同一背景轨并替换原语言对白。
- 合成前先取得可核对的原语音转写和逐句时间信息；不得仅凭标题、封面或少量关键词编造台词。翻译应保留原意，品牌名和专有名词不确定时标记并核对。
- 配音按时段对齐，避免截断、重叠或严重变速；不得宣称已经完成唇形同步，除非确实做了逐帧口型处理。
- 若画面存在烧录中文硬字幕，而输出改为其他语言配音，必须提示字幕与语音语言不一致；未经用户要求不要擅自裁切、遮挡或重做字幕。
- 视频流使用 `-c:v copy`，只重新编码音频；导出后重新执行阶段 5 的元数据清理，并通过 `inspect --require-clean`。

详细的分离、配音、混音与验收命令见 [references/voice-localization.md](references/voice-localization.md)。

## 阶段 5：无损清理元数据

对每条通过初检的视频运行：

```bash
python3 <skill-dir>/scripts/media_guard.py clean \
  <input.mp4> <output_clean.mp4> --report <report.json>
```

脚本执行无损重封装、复查规格、解码和元数据残留。核心 ffmpeg 操作等价于：

```bash
ffmpeg -i input.mp4 \
  -map 0 \
  -map_metadata -1 \
  -map_metadata:s:v -1 \
  -map_metadata:s:a -1 \
  -fflags +bitexact \
  -flags:v +bitexact \
  -flags:a +bitexact \
  -c copy \
  -movflags +faststart \
  output_clean.mp4
```

不要通过重新编码“清洗”元数据。清理后确认：

- `ffprobe` 仍可读取。
- 完整视频解码无错误。
- 分辨率、时长、视频和音频编解码器没有改变。
- `Encoder`、`Writing application`、`Encoded date`、`Tagged date`、`©too`、`creation_time` 等字段不再出现或为空。
- CapCut、剪映、导出时间和设备标识没有残留。

若仍有 `udta/meta` 残留，优先用本机 `exiftool` 定点清除，再做同样验证；没有可用工具时明确报告残留，不得直接宣称已清理。

## 阶段 6：命名、移动与交付

将清理成功的文件移动到输出目录，命名：

```text
{platform}_{关键词或参考slug}_{序号}_{博主名简写}.mp4
```

做过语音处理的文件追加处理标记：

```text
{基础文件名}_no_voice.mp4
{基础文件名}_dub-{目标语言代码}.mp4
```

删除路径分隔符、控制字符和其他文件系统非法字符，避免覆盖同名文件。

交付清单必须包含：

| 序号 | 博主 / 账号 | 原始链接 | 分辨率 | 时长 | 语音处理 | 本地路径 | 与参考相似度 |
| --- | --- | --- | --- | --- | --- | --- | --- |

有参考媒体时填写“高 / 中”；没有参考媒体时写“未使用参考”。另列失败条目和原因，例如解析失败、下载失败、水印明显、规格不符或元数据仍有残留。

最终回复先给出“已交付 N/3 条”，再给清单和简短说明。不要把临时文件、调试日志或失败的半成品放进输出目录。

## 验收规则

只有以下检查全部通过的文件才算完成：

```bash
python3 <skill-dir>/scripts/media_guard.py inspect <output_clean.mp4> --require-clean
```

若返回码非 0，不得把这 1 条计入 3 条交付。
