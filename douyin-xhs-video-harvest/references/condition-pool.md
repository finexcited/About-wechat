# 条件池与问询收敛

只在当前任务需要推导检索条件时读取本文件。目标是用锚点减少提问，同时避免把推断结果误当硬性过滤。

## 视觉画像

解析参考图片或视频时，优先记录页面和关键帧上能直接观察到的信息：

| 画像字段 | 用于 | 观察方法 |
| --- | --- | --- |
| 主体类型 | `content_form` | 看人物动作、镜头结构和画面重心 |
| 人物性别 / 年龄感 / 是否露脸 | `talent` | 看人脸、身形和出镜方式 |
| 服装风格 / 色调 / 场景 | `style` / `visual_tone` | 看服饰、配色、光线和环境 |
| 景别与构图 | `framing` | 中近景、全身、特写、主体位置 |
| 字幕与贴纸 | `editing_style` | 看字体、描边、贴纸和字幕密度 |
| 剪辑节奏 | `editing_style` | 看切镜频率、转场和镜头停留 |
| 推断受众 | `audience` | 结合画面、文案和关键词语义 |
| 规格 | `spec_reference` | 用 `ffprobe` 读取分辨率、宽高比和时长 |

无法可靠判断的字段写“不确定”或“不限”。不要为了填满条件池而编造画像。

## 条件池结构

在内部维护一个可调整的结构，不必展示完整 JSON：

## 问询路径

### 路径 A：有参考媒体

参考媒体已经回答主体和人物锚点。

- 必问：需要排除什么。
- 仅在缺少关键词时追加：确认反推的 1–3 个搜索词。
- 不再问性别、风格、受众或构图。
- 用户消息已经写明排除项时，连排除项也不重复问。

### 路径 B：只有关键词

先问画面主体形式和必须排除项。只有真人出镜形式且首条消息未给人物性别/风格时，才追问人物锚点。

若用户首条消息已经包含形式、性别、风格中的至少两项，跳过问询，直接复述条件池请用户确认。

用户回复“随便 / 都行 / 你看着办”时，采用默认值并开搜，在交付中注明“按默认偏好检索”。

## 映射规则

| 已知信息 | 自动推导 |
| --- | --- |
| 参考媒体画像 | 主体、人物、服装、色调、构图、受众写入条件池，并用于相似度排序 |
| 参考媒体规格 | 作为时长和构图软参考；交付仍须 9:16、短边 ≥1080 |
| Q1=A 口播 | `content_form=口播`；必须露脸；中近景优先；排除纯空镜和纯产品特写 |
| Q1=B 穿搭展示 | `content_form=展示型`；露脸非必须；服装风格由 Q3 决定；排除纯口播无展示 |
| Q1=C 剧情 | `content_form=剧情`；人物至少 1 名；叙事节奏优先；排除教程和测评 |
| Q1=D 纯产品 | 不要求人物；主体维度不适用；受众由关键词推断 |
| Q1=E 都行 | 形式不限；以关键词语义相关性排序 |
| Q3=A/B | 女性；分别偏日常和职场；年龄感默认 18–35 |
| Q3=C/D | 男性；分别偏日常和商务潮酷 |
| Q3=E | 性别和风格不限，仅排序加分 |
| 关键词含“宝妈/学生/职场/健身”等 | 受众取对应人群，不追问 |
| 关键词含“最近/最新/爆款”等 | 排序偏最新或热度，不追问 |
| Q2 任一排除项 | 转成硬性过滤，命中即丢弃 |

未覆盖维度统一写“不限”，只作排序加分。

## 硬条件与软条件

硬条件最多保留以下三类：

1. 用户明确要求排除的内容。
2. 画面主体形式，来自 Q1 或参考媒体的主体类型。
3. 交付规格：9:16、短边 ≥1080、可解码、无明显水印。

人物性别、年龄、服装、色调、构图、受众和剪辑风格默认只用于排序。信息不足时标记“不确定”，不要让软条件把召回池清空。

至少两条硬条件成立才可检索：一条排除项（或内容形式）加规格门槛即可开始。

## 检索停止条件

- 合格 3 条：停止搜索，进入下载。
- 检查到 50 条仍不足：停止，报告数量、最严格维度和放宽建议。
- 平台阻力导致无法继续：报告登录、验证码、页面异常或解析失败，不伪造结果。
